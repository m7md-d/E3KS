# 06 — الصلاحيات والحدود

ما لا أفعله من تلقاء نفسي، مهما بدا صغيرًا أو مفيدًا.

---

## ١. الاعتماديات — أسأل، ولا أقرّر

**ممنوع إضافة أو ترقية أو حذف أي حزمة دون موافقة صريحة.**
يشمل: `pubspec.yaml`، حزم Flutter و Dart، إضافات المنصّات، أي `dependency` أو `dev_dependency`.

**ممنوع تنصيب أي شيء على الجهاز دون موافقة صريحة.**
يشمل: `brew install`، تنصيب Flutter أو أي SDK، `dart pub global activate`،
أدوات سطر أوامر، خطوط، تطبيقات.

الطريقة الصحيحة: أعرض ما أحتاجه، ولماذا، وما البدائل، ثم **أتوقّف وأنتظر**.
أُكمل كل ما لا يعتمد على القرار، وأترك المعتمِد عليه معلَّقًا.

**السبب:** كل حزمة دَيْن دائم — صيانة وحجم وسطح عطب — وكل تنصيب يغيّر بيئة لا أملكها.
هذا قرار المالك، لا قرار المنفّذ.

## ٢. Git — خارج نطاقي تمامًا

**لا ألمس المستودع.** ممنوع:

- `git commit` · `git add` · `git push` · `git pull` · `git merge` · `git rebase`
- إنشاء فرع أو تبديله أو حذفه
- `git checkout` أو `git restore` أو `git reset` أو أي أمر يغيّر شجرة العمل
- `git init` · تعديل `.gitignore` أو `.gitattributes` أو إعدادات Git
- إنشاء pull request أو التعامل مع `gh`

القراءة فقط مسموحة عند الحاجة (`git status`، `git log`، `git diff`) — وللاطّلاع لا غير.

**الالتزام والفروع والدمج قرار المالك وحده.** أنا أعدّل الملفات؛ ما يدخل التاريخ يقرّره هو.

## ٣. الأفعال ذات الأثر الخارجي

أسأل قبل: النشر، الرفع، الإرسال لخدمة خارجية، أي شيء يغادر الجهاز.

## ٤. الحذف والاستبدال

قبل حذف أو استبدال ملف قائم: أطّلع عليه، وأقول ما سيضيع، وأنتظر — إلا إن كان
ملفًا أنشأتُه أنا في هذه الجلسة.

## ٥. ما لم يُطلَب لا يُصنَع

لا توثيق إضافي، ولا سجلّ تغييرات، ولا إعادة تنسيق شاملة، ولا إعادة هيكلة استطرادية
لم تُطلَب. النطاق المطلوب هو المخرَج — لا أوسّعه ولا أضيّقه.
