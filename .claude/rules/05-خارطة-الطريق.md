## المرحلة ١ — المحرّك: docx ✅

1. **طبقة الحاوية** + اختبار الأمانة البايتية (`04` §1). هذا أول كود يُكتب.
2. **الفحص** — استخراج الألوان والخطوط: العدد، الدور، عيّنات النص، فصل ألوان الهوية عن ضجيج الثيم.
3. **التبديل** — الألوان والخطوط، بخريطة من إعداد لا من كود.
4. **بوابة التحقّق** بكامل شروط `02` §9.
5. **اختبارات الانحدار الثمانية** (`04` §3).

**منجَز.** المخرج: حزمة `e3ks_engine` + أمر `e3ks inspect` و`e3ks restyle`.
مُتحقَّق منه على مستندات Word حقيقية: ٢٣ جزءًا تدخل و٢٣ تخرج، الأجزاء غير
المعنيّة مطابقة بايتًا ببايت (١٨ من ٢٣ في التجربة)، حقل `PAGE` سليم،
صفر `w:t` بلا نص، والخطوط أحادية العرض محميّة ومذكورة في التقرير.

## المرحلة ٢ — واجهة macOS ✅

> **البيئة جاهزة:** Flutter 3.47.2 stable · Dart 3.13.2 · Xcode 26.3 · Chrome للويب.
>
> **CocoaPods غير منصَّب — ولا يُنصَّب إلا عند الحاجة الفعلية.**
> لا يلزم ما دام المشروع بلا إضافات تحتاج كودًا أصليًا. أول ما يستدعيه غالبًا

> القرار عند بلوغ الحاجة، لا قبلها — `06` §1.

مسار المستخدم:

```
افتح الملف → فحص → جدول الأثر → عيّن البدائل → معاينة → صدّر
```

### المعاينة — ثلاث طبقات

المطلوب «رؤية ما سيتأثر بوضوح»، لا محاكاة Word. ثلاث طبقات تصاعدية:

| الطبقة | ماذا تُظهر | التكلفة |
|---|---|---|
| **١. جدول الأثر** | كل لون/خط: عيّنة بصرية، العدد، الدور، أين، عيّنة نصّه. قبل ← بعد. | رخيصة، دقيقة دائمًا |
| **٢. معاينة المقاطع** | الفقرات المتأثرة فعليًا، مرسومة بخطوطها وألوانها الحقيقية، قبل/بعد جنبًا إلى جنب. | متوسطة — نملك خصائص الـ run كاملة |
| **٣. معاينة الصفحة** | تحويل إلى PDF وعرض الصفحات. **اختيارية**، تُفعَّل فقط إن وُجد LibreOffice. | مرتفعة، باعتماد خارجي |

الطبقتان ١ و٢ هما المنتج. الطبقة ٣ ترف لاحق، ولا يُبنى عليها شيء أساسي.

### نموذج الهوية

الهوية = **ألوان مسمّاة + خطوط + استثناءات**. ملف JSON يقرأه الإنسان ويشاركه:

```json
{
  "name": "أكاديمية طويق",
  "version": 1,
  "colors": [
    { "name": "الأساسي الداكن", "hex": "#00403C", "role": "primary", "tone": 800 },
    { "name": "الأساسي",        "hex": "#00635D", "role": "primary", "tone": 600 }
  ],
  "fonts": { "latin": "IBM Plex Sans", "arabic": "IBM Plex Sans Arabic" },
  "preserve": ["DejaVu Sans Mono", "Courier"],
  "notes": ""
}
```

قدرات مطلوبة: تسمية الألوان، تجميعها في سلالم (tones)، تصدير/استيراد الهوية،
وتطبيق هوية كاملة على مستند بضغطة واحدة.

## المرحلة ٥ — pdf (بحث)

PDF ليس OOXML: الألوان داخل content streams، والخطوط مضمّنة كمجموعات جزئية (subsets).

- **تبديل الألوان:** ممكن — تعديل معاملات `rg`/`g`/`k` في تدفّق المحتوى.
- **تبديل الخطوط:** صعب جدًا — يستلزم إعادة تضمين الخط وإعادة حساب عرض المحارف
  ومواضعها. **لا نَعِد به.**

القرار: نبدأ بتبديل الألوان في PDF. تبديل الخطوط يبقى بحثًا مفتوحًا حتى نثبت جدواه.
المبدأ ١/١ ينطبق هنا بحرفيّته: PDF لا نستطيع ضمان سلامته = PDF لا نُصدره.
